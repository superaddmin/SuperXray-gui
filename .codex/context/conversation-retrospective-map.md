# 对话复盘地图：运行态网络、部署与治理陷阱

## 目的

沉淀近期多轮发布、部署、服务器审计、OpenWrt/Passwall 分流、AI 域名治理任务中暴露的误判模式、认知盲区和执行偏差，供后续任务先读后动。

## 高频陷阱

### 1. 把“静态配置已修改”误当成“运行路径已生效”

- 典型表现：`uci` / 配置文件已切到新节点，但客户端 `ipify` 仍是旧出口。
- 修正动作：优先读取 `iptables -vnL` 计数、`/tmp/etc/passwall/var`、Passwall/Xray 运行进程参数，再决定是否真的生效。

### 2. 把“页面可访问”误当成“模型接口可用”

- 典型表现：站点首页、控制台能打开，但 API、IDE 插件、流式响应失败。
- 修正动作：分开验证主站、控制台、API、静态资源、插件代理域名。

### 3. 混淆显式 SOCKS、透明 REDIRECT、TPROXY 和 DNS 劫持

- 典型表现：用单个 `curl -x socks5h://...` 的结果，推断整条透明代理链。
- 修正动作：明确当前验证的是哪一层路径；显式 SOCKS 成功不代表透明 ACL 一定成功。

### 4. 在任务域切换时不重述“当前主问题”

- 典型表现：把上游同步、构建发布、线上部署、路由器审计、AI 域名治理混成一个大问题。
- 修正动作：跨域前先写出“当前主问题 / 暂挂项 / 证据边界 / 回滚边界”。

### 5. 用单视角证据下结论

- 典型表现：只看客户端、只看路由器、或只看服务器某一侧。
- 修正动作：网络和分流问题至少要求双视角证据：客户端 + 中间设备，或中间设备 + 服务器。

## 运行态证据优先级

1. 客户端观测到的实际出口/失败模式。
2. 中间设备（OpenWrt/Passwall）ACL 计数、运行缓存、进程参数。
3. 服务器侧真实运行进程、端口、出口与日志。
4. 静态配置文件和设计预期。

## 结论模板

对网络与代理类任务，最终结论至少回答：

- 当前客户端在什么网段/SSID/接口。
- 实际命中的是哪条 ACL / routing rule。
- 真实出口是谁。
- 当前问题属于客户端、中间设备、服务器还是配置设计。
- 回滚点是什么。

## 本次服务器部署复盘（脱敏）

以下事实来自一次真实的 Linux amd64 服务器部署，值已全部脱敏；后续服务器任务应优先参考 `superxray-server-deployment` 技能：

- Release 包部署前先核对 `uname -m`、面板版本和 Xray 版本；错误架构或缺少 GeoIP/GeoSite 会让运行态检查失去意义。
- 修改 systemd unit 后必须 `systemctl daemon-reload`。重启期间偶见“Xray 尚未运行”的竞态警告，最终判断要看随后进程、监听端口和实际代理链路。
- 订阅服务只用 GET 和 `/<subId>/diagnose` 验证；不能用 HEAD，也不能只凭 HTTP 200 判断有节点。
- 反代的 `/sub/`、`/json/`、`/clash/` 都必须传 `X-Forwarded-Host`，并固定公开订阅 URI，否则节点主机可能从请求来源回退得到错误地址。
- 三个月/六个月订阅要使用独立 `subId`/客户端，`expiryTime` 写 Unix 毫秒并按日历月计算；Mixed 账号级 `expiryTime` 当前不会被订阅生成器读取。
- 通用 SOCKS5 是 `mixed` 入站的账号字段和 `socks5://` URI，必须分别验证主机、端口、用户名、密码以及真实出口；它与 Clash/Mihomo YAML URL 是两种交付物。
- SOCKS5 使用 UDP 时追加 `ss -lunp`、云安全组和本机防火墙检查；TCP 端口可达不能证明 UDP 可用。
- 本地临时 Xray 客户端端口先探测空闲，失败后换临时端口并清理残留进程；不要把固定端口失败误判为服务器节点故障。
- 证书菜单或签发命令的成功提示不是握手证据；必须用实际 HTTPS GET/HEAD（服务支持时）或 `openssl s_client` 核对证书链和 SAN。
